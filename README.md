# Проектирование БД для аналитических задач: банк (данные Berka)

Командный проект по дисциплине «SQL и базы данных» (ВШЭ). Делаем вдвоём.

Предметная область: розничный банк — клиенты, счета, транзакции, кредиты, карты, платёжные поручения.
Данные для наполнения: открытый датасет **Berka** (чешский банк, соревнование PKDD'99).

## Что сдаём

1. Пояснительная записка (docx/pdf) — части 1 и 2.
2. SQL-скрипты (DDL/DML) с комментариями — папка `sql/`.
3. Бэкап базы с аналитическим слоем (`pg_dump`).

## Структура репозитория

```
data/raw/   исходные файлы Berka (не коммитим, каждый скачивает сам)
sql/        скрипты по порядку запуска: 00_, 01_, 02_ ...
docs/       схемы (концептуальная, логическая, физическая), черновики записки
```

## Как развернуть базу у себя

1. Установить PostgreSQL (16 или новее) и pgAdmin или DBeaver.
2. Скачать данные Berka и положить 8 файлов в `data/raw/`:
   `account`, `client`, `disp`, `order`, `trans`, `loan`, `card`, `district` (`.asc`, разделитель `;`).
   Источник: архив соревнования PKDD'99 или копия «Berka dataset» на Kaggle.
   Описание полей: https://relational.fel.cvut.cz/dataset/Financial
3. Создать пустую базу, например `bank`.
4. Из корня репозитория запустить скрипты из `sql/` по порядку номеров:
   ```
   psql -d bank -f sql/00_....sql
   ```

| Этап | Что делаем | Критерии |
|---|---|---|
| 1 | Контекст, функциональные требования, бизнес-правила | K1–K2 |
| 2 | Концептуальная модель, источники данных и НСИ | K3–K4 |
| 3 | Логическая модель (Crow's foot), ограничения, 3НФ | K5–K7, K9 |
| 4 | Физическая модель, типы, реализация в PostgreSQL, загрузка | K8, K10–K13 |
| 5 | Роли, сценарии, отчёты (таблицы 1.1, 1.2, 2.1) | K14–K15 |
| 6 | Аналитический слой: VIEW и MATERIALIZED VIEW (таблица 3.1) | K16–K17 |
| 7 | Аналитические запросы: подзапросы, CTE, окна, функции, массивы, jsonb | K18–K23 |
| 8 | Триггер, оптимизация (EXPLAIN), тестирование | K24–K26 |
| 9 | Пояснительная записка | K27 |

## Как работаем вдвоём

- Каждый у себя запускает одни и те же скрипты из `sql/` — базы получаются одинаковыми.
- Перед работой: `git pull`. После: `git add`, `git commit`, `git push`.
- Кто за что отвечает — в файле `КОМАНДА.md` (заполнить).
